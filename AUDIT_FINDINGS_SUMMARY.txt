BUG #1: REVISION FILES CONTAMINATING DETAIL VIEW
File: src/lib/authorManuscriptDetails.ts (lines 78-85)
Severity: MEDIUM
Status: ✅ FIXED

Description:
  The fetchAuthorManuscriptDetails() function queries manuscript_files without
  filtering out revision files (revision_id != null). This could cause revision
  files to appear mixed with the original submission files.

Impact:
  - Newly submitted manuscripts: NONE (no revisions yet)
  - Revised manuscripts: Files would show both original + revision files
  - Detail page clarity: Could confuse users about which files are current

Fix Applied:
  Added .is('revision_id', null) filter to the query
  Now matches behavior of getManuscriptFiles() in workflow.ts

Commit: c97f32e

Before:
  .select('*')
  .eq('manuscript_id', manuscriptId)
  .order('uploaded_at', { ascending: false })

After:
  .select('*')
  .eq('manuscript_id', manuscriptId)
  .is('revision_id', null)  // ← ADDED
  .order('uploaded_at', { ascending: false })

BUG #3: MISSING FILENAME SANITIZATION IN UPLOAD
File: src/components/NewSubmissionFlow.tsx (line 394)
Severity: MEDIUM
Status: ✅ FIXED

Description:
  Filename wasn't sanitized before being used in storage path. Special
  characters (spaces, slashes, etc.) could cause storage issues.

  uploadManuscriptFile() sanitizes, but NewSubmissionFlow didn't.

Impact:
  - Files with special chars: Storage path could be malformed
  - RLS policy checks path format: Could fail with special chars
  - User experience: Unexpected behavior with certain filenames

Fix Applied:
  Added regex filter to sanitize filename before upload

Commit: c97f32e

Before:
  const fileKey = `${user.id}/${Date.now()}-${file.name}`;

After:
  const sanitizedFileName = file.name.replace(/[^a-zA-Z0-9.]/g, '_');
  const fileKey = `${user.id}/${Date.now()}_${sanitizedFileName}`;
